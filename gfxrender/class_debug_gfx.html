Detailed Description

Draws debug points and lines.

One DebugGfx can draw any number of either, individually or in batches, over its lifetime – keep one around (e.g. as a member alongside your other shaders) rather than building one per marker/line; it owns a single shared shader used for all of it, so nothing is duplicated by drawing both points and lines from the same instance. Example:

// as a member, alongside your other shaders:
DebugGfx debug_gfx_;
// later, to draw:
debug_gfx_.DrawPoint(light_position, 0.1f, Color(1, 1, 0), view, proj);
debug_gfx_.DrawLine(p0, p1, Color(1, 1, 0), view, proj);
// or many lines sharing one draw call (e.g. a per-vertex normals
// visualization) -- rebuild the Mesh only when the lines actually
// change, not every frame:
Mesh normals_mesh = BuildDebugLineMesh(segments);
debug_gfx_.DrawLineMesh(&normals_mesh, Matrix4(), view, proj);

Draws a single line segment from p0 to p1, tinted color, half_width world-space units wide.

Builds a fresh, tiny mesh every call, so for many lines at once (e.g. a per-vertex normals visualization), build one Mesh with BuildDebugLineMesh() and call DrawLineMesh() instead of calling this in a loop – that shares one mesh/one draw call across every segment rather than paying for a mesh (and a GPU upload) per line per frame.

Draws a Mesh already built by BuildDebugLineMesh() – for many lines sharing one draw call.

Each segment shows in the color it was given when the mesh was built (baked into its own vertices), not a single uniform color. model, view, and proj are applied the same way – and taken in the same order – as every other Draw() in this codebase (UnlitShader, GouraudShader, PhongShader, ...): pass Matrix4() for model if mesh's segments were already given in world-space coordinates; pass mesh's own source model matrix instead if they're in some other space (e.g. a per-vertex normals visualization built from a source mesh's own local-space data, which needs that mesh's model matrix to line up with it on screen).

Draws one point marker: a small quad, size world-space units across, centered at world-space position center, tinted color, always facing the camera described by view.

Textured with a soft- edged circular mask (gfx_libs/gfxrender/data/dot.png, loaded once on first use) rather than left a flat-shaded square, so it reads as a dot/glow rather than a visible quad – GL_BLEND is enabled with ordinary alpha blending around just this draw call, then disabled again afterward (the same "known state after, not a saved-and- restored one" convention every other blended draw in this codebase follows, e.g. Camera & Shading (4)'s own multi-light accumulation) so the mask's transparent corners actually show through instead of being written opaquely. Lazily builds its shared unit-quad mesh, loads that texture, and builds its shader the first time this (or any other Draw*() method) is called, so there's no separate setup step.
