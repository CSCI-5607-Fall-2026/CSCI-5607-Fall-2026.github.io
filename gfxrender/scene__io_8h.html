struct  SceneMaterialDesc
 A material's shading properties – the same fields GfxRender's MaterialProperties has (see a consuming app's own ToMaterialProperties() for the conversion), plus a texture path rather than an already- loaded Texture2D, since this struct is meant to be plain, serializable data with no OpenGL state of its own. Named SceneMaterialDesc, not Material, so it doesn't collide with GfxRender's own Material class (a .mtl file loader/holder – see material.h) when both are visible in the same translation unit. mesh_file/texture are always bare filenames (never absolute paths), meant to be resolved against a search path built from the scene file's own location, so a scene and the files it references stay portable across machines and grading. struct  SceneObjectDesc
 One object in the scene: either one of the four canonical analytic primitives ("sphere"/"cube"/"cylinder"/"cone") or an arbitrary triangle mesh loaded from an .obj file (shape_type == "mesh", mesh_file set to that .obj's bare filename) – plus its full model transform and material.  Which shading style a Draw() call should use for one object – iModel (5) on, this is a per-*object* choice (see SceneMaterialDesc:: shader_style below), not a whole-scene setting, since it lives on the same struct as the rest of that object's own material rather than SceneDesc itself: conceptually part of "how this object's surface looks," the same as its reflectance values are, not a separate camera- or scene-level concern. A consuming app maps this to whichever of its own given shader classes (UnlitShader/GouraudShader/PhongShader/ HighlightShader) match; this enum only names the style, not which C++ class implements it, the same separation LightType keeps from PointLight/DirectionalLight.
