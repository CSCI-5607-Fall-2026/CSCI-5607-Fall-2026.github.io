bool Material::LoadAllFromFile ( const std::string & path,
std::map< std::string, MaterialProperties > * out )
static

Loads every named material block from a Wavefront .mtl file – unlike LoadFromFile(), which only reads the first – into *out, keyed by each block's own name (the identifier right after "newmtl"), for a multi-material .obj (e.g.

bmw.obj + bmw.mtl, one material per car part) loaded via Mesh::LoadMultiMaterialOBJ(), which returns that same per-part name so it can be looked up here. Same search path, same fields read (Ns/Ka/Kd/Ks/map_Kd), and same per-material map_Kd resolution (relative to path's own directory) as LoadFromFile(); a block with no map_Kd line gets an uninitialized surface_texture, same as LoadFromFile()'s own "no texture" case. *out is cleared first, so on an empty path or a file that can't be opened/has no newmtl blocks at all, *out ends up empty rather than partially filled or left with a stale previous call's contents. Returns true if at least one block was read.

◆ LoadFromFile()

bool Material::LoadFromFile ( const std::string & path)

Loads a Wavefront .mtl file, searched the same way as RenderPlatform::FindGfxRenderDataFile() (current directory, a "data" subdirectory of it, then GfxRender's own installed/build data directories).

Only the file's first newmtl block is read – a real .mtl (e.g. bmw.mtl) can hold many named materials, but a Material only ever holds one at a time. Within that block, only Ns (shininess), Ka (ambient_reflectance), Kd (diffuse_reflectance), Ks (specular_reflectance), and map_Kd (surface_texture, resolved relative to the .mtl file's own directory – the Wavefront convention) are read; Ni/Tr/d/illum/Ke are for a later, raytracing-related assignment and are ignored. On an empty path or a file that can't be parsed, resets properties() to MaterialProperties()'s own defaults and clears the texture, rather than leaving whatever was previously loaded. Returns true on success.

◆ LoadTexture()

bool Material::LoadTexture ( const std::string & path)

Loads just properties().surface_texture, searched the same way as LoadFromFile() (RenderPlatform::FindGfxRenderDataFile()) – for setting a texture on its own, without touching Ns/Ka/Kd/Ks or going through a .mtl file.

An empty path or a load failure clears the texture (surface_texture becomes an uninitialized Texture2D) rather than leaving a stale one applied. Returns true on success.

◆ texture_path()

const std::string & Material::texture_path ( ) const
inline

The path last passed to LoadTexture(), or map_Kd's own value if the current texture came from LoadFromFile() instead – "" if there's currently no texture.

This is the path as given/read, not resolved to an absolute location; useful for an app that wants to show the user what's currently loaded (e.g. in a text field) without duplicating that bookkeeping itself.
